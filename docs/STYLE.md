# 집필 지침 (콘텐츠 작성자용 — 사람과 에이전트 모두)

이 교재의 독자는 **산수만 할 줄 아는 사람**이다. 목표는 그 독자를 SVD와 LoRA를 스스로 설명할 수 있는 수준까지 데려가는 것이다.
유클리드의 『원론』처럼, 당연해 보이는 것도 "왜?"라고 물을 수 있는 자리마다 **앞에서 이미 답했는지** 확인하고, 답한 자리를 링크로 잇는다.

## 1. 문장

1. 내용이 어렵고 추상적일수록 멋대로 줄이거나 추상화하지 않는다. 한 걸음씩 쓴다.
2. 주어와 목적어를 생략하지 않는다. "이것은 …" 대신 "행렬 A의 첫째 열은 …"처럼 무엇을 가리키는지 밝힌다.
3. 필요한 부사어(언제, 어디서, 무엇에 대해)를 적는다. 수식 대상과 범위를 관형어로 분명히 한정한다.
4. 설명하는 문장은 한자어보다 쉬운 말, 압축된 명사형보다 풀어 쓴 서술형을 쓴다.
   - 나쁨: "선형성 보존 여부 확인을 통한 판별" → 좋음: "덧셈과 스칼라 곱이 그대로 유지되는지 확인해서 가려낸다"
   - 단, **대상을 가리키는 이름(용어)은 표준 학술 용어**를 쓴다(행렬식, 고윳값, 특이값 …).
5. 비유는 **표현하려는 영역을 빠짐없이, 넘치지 않게** 덮을 때만 쓴다. 맞는 비유가 없으면 쓰지 않는다. 비유를 쓰면 `> [!비유]` 상자 안에 쓰고, 비유가 **어디서 깨지는지**를 같은 상자에 한 문장으로 적는다.
6. 규칙이나 정의를 쓸 때는 두 개 이상의 예로 교차 확인한 뒤 쓴다. 본문의 규칙과 예가 어긋나지 않는지 다시 본다.
7. 칭찬하거나 들뜨는 말투("놀랍게도!", "아주 쉽습니다")를 쓰지 않는다. 담담하게, 그러나 친절하게 쓴다. 문체는 "~다" 체.

## 2. 용어와 기호 (검증기가 강제한다)

- 새 용어는 그 용어를 정의하는 노드의 `introduces.terms`에 선언하고, 본문에서 **정확히 그 자리에** `[표면형](def:용어id)`로 표시한다.
- 이미 정의된 용어를 쓸 때는 `[표면형](t:용어id)`. 매번 표시할 필요는 없다. **노드에서 처음 나오는 자리는 자동으로 용어 링크가 된다**(첫 등장 자동 링크, 위키백과 방식, 2026-10-03 결정). 그래서 한참 뒤의 노드에서도 용어에 마우스를 올리면 정의와 영어 이름이 뜬다.
  - 자동 링크는 검증기와 같은 어휘 목록(`ko`와 `surfaces`, `everyday` 제외)으로 읽는 순서대로 찾는다. 직접 `t:`로 표시한 자리가 있으면 그 앞의 첫 등장만 자동으로 잇는다.
  - 소제목, 관문과 점검의 보기 단추에는 링크를 달지 않는다(보기를 누르면 링크로 떠나 버린다). 힌트와 보기별 해설 안의 링크는 본문의 첫 등장 링크를 대신하지 않는다(펼쳐 볼 때만 보이므로).
- 영어 표준 용어(`en`)는 모든 용어에 적는다. 정의하는 자리(`def:`)와 노드 머리의 종류 배지에만 위첨자로 붙고, 그 뒤에는 용어 미리보기에 뜬다.
- **아직 정의되지 않은 용어를 미리 언급해야 하면** `[표면형](fwd:용어id)`로 "예고"한다. 표시 없이 쓰면 검증기(P008)가 경고한다.
- 왜? 칩 `[질문?](why:노드id)`는 **반드시 앞쪽 노드**를 가리킨다. 답이 뒤에 있으면 칩을 달지 말고, 노드의 `openWhys`에 `{ q, answeredBy: '뒤 노드 id' }`로 적는다(P018로 보고서에 "미뤄 둔 왜?"로 뜬다). 답이 아예 없으면 `answeredBy: null`(P007).
- 한 기호는 교재 전체에서 한 뜻만 가진다. 새 기호를 정하기 전에 `docs/SYMBOLS.md`의 예약표를 확인한다.

### 이름 충돌 규칙 (이미 정한 것)
| 충돌 | 결정 |
|---|---|
| 계수(係數, coefficient) vs 계수(階數, rank) | coefficient = **계수**, rank = **랭크** |
| 외적(cross product) vs 외적(outer product) | outer product = **바깥곱**. cross product는 쓰지 않는다 |
| 투영 vs 사영 (projection) | **사영**으로 통일. 수직으로 내리는 것은 **정사영** |
| 성분 (벡터의 칸) vs 원소 (행렬의 칸) | 둘 다 **성분**. 행렬의 열은 벡터이므로 열의 성분 = 행렬의 성분이다 |
| 반대수 vs 덧셈 역원 (additive inverse) | **덧셈 역원**. 반대수는 표준 용어가 아니다 |
| 낮은 랭크 근사 vs 저랭크 근사 | **저랭크 근사** |
| 신경망의 layer vs 9권 SVD의 랭크 1 항 | layer = **레이어**(선형 레이어). 랭크 1 항 = **'층'**(비유 이름, 아래) |

### 이름 표기 규칙 (2026-10-04 결정)
- **긴 이름의 줄임**: 처음 정의하는 자리에서만 풀어 쓰고, 바로 뒤에 "이 교재에서는 이 뒤로 줄여서 ○○라 적는다"를 밝힌다. 줄인 이름은 용어의 `surfaces`에 넣어 호버가 되게 한다. 기호표의 뜻풀이(`meaning`)는 따로 찾아 읽는 곳이므로 풀어 쓴 이름을 그대로 둔다.
  - 왼쪽 영공간 → 좌영공간, 오른쪽/왼쪽 특이벡터 → 우특이벡터/좌특이벡터
- **비유로 지은 이름**은 그 뜻으로 쓸 때마다 작은따옴표로 감싼다: '층'. 따옴표는 비유라는 표시이고, 따옴표까지 포함한 표기가 용어의 표면형이다(그래서 한 글자 이름도 자동 링크가 된다). 비유의 원래 뜻(실제 층)으로 쓸 때는 따옴표를 붙이지 않는다. 비유 상자에 덮는 범위와 깨지는 곳을 적는 규칙(1-5)도 그대로 따른다.
- **한 글자 이름**(향)은 다른 낱말 속에 섞이기 쉽다(방향, 영향, 편향, 향하다). 용어에 `boundary: true`를 켜면 앞에 한글이 붙지 않고 뒤에 조사·공백·문장 부호가 올 때만 찾는다. 혼동이 큰 이름은 `everyMention: true`로 노드마다 첫 등장만이 아니라 **모든 등장**에 링크를 단다(2026-10-04 결정: 향). 정의하는 자리에서만 한자를 병기한다: 향(向).
- **모든 용어의 한국어 이름이 표준인지 확실하지 않으면 사용자에게 먼저 묻는다.**

## 3. 노드 종류
- `ax` 공리(axiom): 증명하지 않고 받아들이기로 정한 출발점. 왜 받아들이는지(어떤 경험과 맞는지)를 적는다. 공리를 바꾸면 다른 수학이 된다.
  - 공리와 **규약**(convention)을 섞지 않는다. 규약은 여러 표기 가운데 하나를 고른 것이고, 바꿔도 수학이 같다(벡터를 세로로 적기, 행렬의 모양). 규약인 자리에는 "이것은 규약이다"라고 밝힌다. "약속"이라는 낱말은 이 두 뜻 어느 쪽으로도 쓰지 않는다(2026-10-03 결정).
  - 공리 노드에는 증명을 넣지 않는다. 공리에서 나오는 결과는 바로 뒤의 `prop` 노드에 둔다(예: `ax.arith` → `prop.arith-first`).
- `def` 정의: 이름 붙이기. 참/거짓이 없다. 그러나 "왜 하필 이렇게 정의했나?"에는 답한다.
- `prop` 명제: 반드시 `proof`(증명)를 단다. 증명은 앞의 공리, 정의, 명제만 쓴다. 쓰는 것마다 `why:` 칩이나 `t:` 표시를 단다.
- `exp` 탐구: 손으로 만지며 다음 개념을 예감하게 하는 장면 중심 노드.

## 4. 본문 구성 (권장 순서)
1. **질문으로 연다.** 이 노드가 답할 질문 한 문장.
2. 장면(`::scene`)으로 먼저 손에 쥐여 준다.
3. 정의/명제를 적는다. 정의는 `$$…$$`로 따로 세운다.
4. 두 개 이상의 예.
5. 증명(명제라면 `proof`).
6. 점검 문제(`checks`) 1~3개. 오답 선택지는 **흔한 오해**를 반영한다. 해설은 왜 그 오해가 틀렸는지 짚는다.
7. 해당 코드가 있으면 `code: ['함수이름']` (src/la/*.ts의 export).

## 4-1. 예측 먼저 (2026-10-02 결정)
노드는 "읽고 나서 확인"이 아니라 **"예측하고 나서 읽기"**로 짠다. 본문 중간의 `::predict id` 자리가 관문이고, 학습자가 예측을 확정해야 그 뒤의 본문이 열린다(증명·점검은 마지막 관문 뒤에 열린다).

- **개수**: 본문을 쓴 노드마다 관문 1~3개. 노드의 핵심 통찰 바로 앞에 둔다.
- **누설 금지**: 관문 **앞의** 글, 수식, 장면 매개변수가 답을 미리 보여 주면 안 된다. 검증기가 잡지 못하므로 쓰는 사람이 확인한다. (예: Ax를 예측시키기 전에 Ax를 그리는 장면을 두지 않는다.)
- **오답 보기 = 실제 오해**: 선택형의 오답은 흔한 착각(행과 열을 바꿔 읽기, 제곱을 빠뜨리기, 입력 공간과 출력 공간 혼동 …)이어야 한다. `why[k]`에 "이것을 골랐다면 무엇을 착각했는가"를 적는다. 정답의 `why`는 짧게, 본문이 이어서 설명한다.
- **그림형을 우선 고려**: "어디로 가는가", "어느 방향인가"를 묻는 관문은 `kind: 'point'`로 손으로 끌어 놓게 한다(target `Ax`, `eig`, `v1`). 정답은 `src/la`가 계산한다.
- **관문 뒤의 첫 문장은 답을 받는다**: "답은 네 개다." 처럼 예측의 결과를 받고 나서 설명을 잇는다.
- 학습자는 "예측 없이 보기"로 건너뛸 수 있고, 왜? 칩을 따라 들어오거나 이해 표시를 한 노드는 펼쳐진 채로 열린다. 그러므로 관문 뒤의 내용도 **찾아보기용으로 읽혀도 자연스러워야** 한다.

### 관문의 난이도 (2026-10-02 결정: "더 어려워도 된다, 대신 힌트")
- **읽은 것을 되풀이하게 하지 않는다.** 관문은 위에 적힌 내용에서 **추론 한 걸음 이상**을 요구해야 한다. 좋은 관문의 세 유형:
  1. *새 경우에 적용*: 방금 배운 사실을 처음 보는 행렬·상황에 쓰기 (예: 고윳값 3, 1을 알 때 A + 2I의 고윳값)
  2. *결과를 예측*: 아직 증명하지 않은 사실의 결과를 먼저 걸기 (예: 대칭이 아닌 행렬의 최대 늘어남 방향 끌어 놓기)
  3. *경계를 묻기*: 성질이 깨지거나 생기는 경계 (예: 회전 뒤 늘이기의 배율이 얼마일 때 고유 방향이 생기는가)
- **오답 보기 하나는 "거의 맞는" 답**으로 둔다: 올바른 추론에서 한 군데만 미끄러진 답(제곱 빠뜨리기, 부호 하나, 입력/출력 공간 혼동).
- **힌트**: 맞힐 사람이 절반이 안 될 것 같은 관문에는 `hints`를 1~3개 단다. 단계를 지킨다.
  - 힌트 1: 어느 앞 노드의 어떤 사실을 쓰면 되는지 (링크 가능)
  - 힌트 2: 계산이나 그림의 실마리 (한 줄의 중간 결과)
  - 힌트 3(선택): 방법은 거의 다 보여 주되 **답은 말하지 않는다**
  - 힌트를 몇 개 열었는지는 기록에 남는다. 힌트는 벌이 아니라 사다리다.

## 5. 수식
- KaTeX 문법. 본문은 `String.raw` 템플릿이므로 역슬래시를 두 번 쓰지 않는다.
- 색 매크로(색도 기호다): `\ca{…}` 주황(1열/e₁) · `\cb{…}` 청록(2열/e₂) · `\cc{…}` 보라(3열/e₃) · `\cx{…}` 노랑(입력 x) · `\cy{…}` 분홍(출력 Ax) · `\cu{…}` 하늘 · `\cv{…}` 연두. 그 밖에 `\R` = ℝ, `\T` = 전치 기호. (src/content/katex-macros.ts)
- 인라인 코드는 본문에서 \`이름\` (백틱 앞에 역슬래시. String.raw 템플릿이기 때문).
- 동기화 고리: 수식 안에서 `\h{키}{식}` → 장면/행렬 편집기의 같은 키와 함께 빛난다.
  - 표준 키: `col1`, `col2`, `col3` (행렬의 열), `a11`…(칸), `x`(입력 벡터), `Ax`(출력), `det`(넓이), 장면마다 문서화한 키.

## 6. 장면(scene)
- 파일 하나 = `src/scenes/<id>.ts`, default export `SceneFn`. 파일 이름이 id다.
- `src/scenes/transform-grid.ts`가 기준 예시다. 배치는 `layout()`, 수치 표시는 `readout()`, 조작은 `src/ui/widgets.ts`.
- 색은 `src/render/colors.ts`의 `C`만 쓴다. **색도 기호**다: 주황 = 1열/e₁, 청록 = 2열/e₂, 노랑 = 입력 x, 분홍 = 출력 Ax.
- 그리기는 `Plane`(2D) / `Space`(3D)의 도구만 쓴다. 매 프레임 DOM을 새로 만들지 않는다(60fps).
- 장면 맨 위 주석에 매개변수와 동기화 키를 적는다.
- 그림에 보이는 모든 수는 `src/la`의 함수로 계산한다(그림과 코드가 같은 수학을 쓴다는 보장).
