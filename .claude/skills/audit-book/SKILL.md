# 장 감사 절차

인자: 장 id 하나(예: `c1`). 없으면 저자에게 어느 장인지 묻는다.
원칙: 감사는 저자의 검토를 **대신하지 않는다**. 감사를 거쳐도 노드를 "검토함"으로 기록하지 않는다(`npm run review -- mark`는 저자만 한다).

## 1. 준비
- `npm run verify`를 돌려 error가 0인지 확인한다. error가 있으면 감사 전에 저자에게 알린다.
- 이 장에 대한 이전 감사 보고서(`docs/audit/<장>.md`)가 있으면 읽어 둔다. 이미 판정한 지적을 다시 묻지 않기 위해서다.

## 2. 감사 맡기기
- `content-auditor` 에이전트를 **하나만** 부른다(에이전트는 동시에 2개까지만 돌리는 것이 이 프로젝트의 약속이고, 감사는 하나로 충분하다).
- 프롬프트: 장 id와 장 폴더 경로(`src/content/cNN-…/`), 그리고 "보고서 형식대로, 파일을 고치지 말고 보고서만 돌려 달라"는 말. 원고를 쓴 쪽의 설명이나 변명을 덧붙이지 않는다(감사의 독립성).
- 이 세션에 `content-auditor`가 아직 등록되지 않았으면(세션 시작 뒤에 만든 경우), 일반 에이전트에 `.claude/agents/content-auditor.md`의 본문 전체를 지시로 넘긴다.

## 3. 지적을 하나씩 다시 확인하기 (가장 중요)
감사자도 틀릴 수 있다. 지적마다 원문 자리를 직접 열어 읽고, 수치는 `src/la`로 다시 계산해서 셋 중 하나로 판정한다.
- **맞음**: 지적이 옳다.
- **틀림**: 지적이 틀렸다. 왜 틀렸는지 한 문장으로 적는다(예: openWhys에 이미 적혀 있다, 앞 노드 X에서 증명했다).
- **저자 판단 필요**: 고칠 방향이 여럿이거나, 용어 이름처럼 저자가 정할 일이다. 한국어 이름이 표준인지 확실하지 않은 것은 언제나 여기에 넣는다.

## 4. 기록
`docs/audit/<장>.md`에 남긴다. 형식:

```
# <장 id> <장 제목> 감사 기록

## <날짜> 감사
- 감사자: content-auditor (지적 n개 → 맞음 n · 틀림 n · 저자 판단 n)

| id | 노드 | 종류 | 심각도 | 요약 | 판정 | 처리 |
|---|---|---|---|---|---|---|
| c1-01 | def.vector | B | 빈틈 | … | 맞음 | 고침(커밋 …) |

### 지적 원문과 판정 근거
(감사자의 지적 원문을 그대로 붙이고, 각 지적 아래에 판정 근거를 적는다)
```

## 5. 고치기
- **맞음**이면서 판단이 필요 없는 것만 고친다(정답 번호, 계산 실수, 빠진 근거 링크, 기존 노드로 메울 수 있는 증명 단계 등). `docs/STYLE.md`의 문장 규칙을 지킨다.
- 공리를 더하거나 노드를 새로 만들거나 나누는 일처럼 구조를 바꾸는 수정은 저자 판단으로 돌린다.
- 고친 자리는 기록 표의 "처리" 칸에 적는다.

## 6. 저자에게 보고
- 판정 요약(맞음/틀림/저자 판단 개수), 고친 것, 저자 판단이 필요한 것을 보고한다.
- 저자 판단이 필요한 것은 하나씩 근거와 선택지, 내 추천을 붙여 묻는다.

## 7. 마무리 검사
`npm run verify`, `npm test`, `npm run typecheck`, `npm run e2e`, `npm run sweep`를 모두 돌려 결과를 그대로 보고한다. 커밋은 저자가 하라고 할 때만 한다.
